### 31.3 M1-03｜实现受控 Hermes HTTP Adapter 与状态映射

**负责人 / 复核：** agent / backend。**依赖：** M1-01、M0-05。

**先读现有材料：** `reference_code/adapter_contract.py`；`execution/templates/hermes-capability-probe.yaml`。

**具体实施：**

1. 实现 run_stage/cancel/health/capabilities，自有协议保持稳定。每个角色取得独立受控 runtime，调用内部 /v1/runs，保存 job_id、step_id 与 hermes_run_id 的映射。[S28][S29]
2. 输入只包含本次必要配置与指定 Skill；provider/model 由后端白名单注入，忽略教师提交的路由字段。不传 previous_response_id 或其他任务历史；唯一会话只解决关联，不替代权限隔离。
3. 状态映射：上游 completed 还需 completed/partial/error 一致和 JSON/schema 校验；失败或迭代耗尽不能因 HTTP 200 视作 SUCCEEDED。未知枚举视为运行异常。[S28]
4. 事件只转换成批准的计数、阶段、工具名称和脱敏错误，不把工具 preview 或原始 reasoning 全量透传浏览器。用量缺失标记 unknown，不当成零费用。
5. 取消调用 stop 并等待/核查实际结束；本地取消标志独立控制是否继续派发与写回。上游停不下时执行外部期限/隔离进程回收，已发生费用不清零。

**应交付的应用文件：** `services/hermes_adapter/http_adapter.py`；`services/hermes_adapter/runtime_factory.py`；`services/hermes_adapter/status_map.py`。

**验证与通过证据：** 1）同一规格通过实际 Hermes 产生可校验结果，保存实际版本和模型追踪；无 Key、404 run、partial、坏 JSON 均明确失败。 2）断开等待再恢复时按已有 run_id 查询，不无条件再 POST；测试 cancel 后迟到结果不进入当前卷。

**失败时处理：** 上游创建响应丢失时进入 RECONCILING 状态查证；无可靠恢复能力不得自动重发计费调用，转人工或授权重试。

**关联验收：** MIN-04、MIN-N03、MIN-N06、FULL-04、FULL-18。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 31.4 M1-04｜实现任务投递、幂等和最小恢复机制

**负责人 / 复核：** backend / qa。**依赖：** M1-02、M1-03。

**先读现有材料：** `infra/compose.yaml`；`configs/business-policy.example.yaml`。

**具体实施：**

1. 默认从 M1 使用 Celery/RabbitMQ，以单 Worker/低并发起步；不要再建一套模型推理循环。任务只投递 ID，正文从授权仓储读取。
2. 业务事务同时写 jobs 与 outbox；派发器确认消息投递后更新 outbox。至少一次投递可能重复，消费者以 stage_key 和 attempt 加租约/栅栏令牌去重。[S33]
3. 模型网络重试由 Hermes 已确认层负责；Worker 只恢复阶段，不对同一计费请求无限 autoretry。分别保存 delivery_attempt、request_attempt、repair_attempt，语义不能混用。
4. 结果写回要求租约有效、期望 revision 一致、未取消、预算允许；重复消息只能读已有结果。每次外部调用前预留额度，使用后结算或标记 unknown。
5. 实现轻量故障巡检：过期租约查实际 run 状态，仍在执行就继续监控；已完成补写，未知不盲目重新生成。

**应交付的应用文件：** `services/worker/celery_app.py`；`services/worker/tasks.py`；`services/worker/outbox.py`；`services/worker/leases.py`。

**验证与通过证据：** 1）同一消息投递两次只产生一个领域结果；刷新网页不新建任务。 2）测试 Worker 在调用前、获得 run_id 后和写回后分别崩溃，观察恢复路径；不能承诺外部 API 计费恰好一次。

**失败时处理：** 队列或数据库不可用则停止接单或暂存明确状态，不返回“已生成”；毒消息进入隔离队列，保留可定位原因。

**关联验收：** MIN-05、MIN-N06、FULL-15、FULL-16、FULL-17。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。
