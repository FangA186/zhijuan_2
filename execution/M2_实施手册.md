## 32 M2 执行：最小可用试卷闭环

进入条件：G-BOOT 已通过，具备真实任务与持久化。退出产物：三学段各 5 题 20 分、盲解与工具检查、有限修订、编辑保存、草稿 PDF/JSON、G-MIN 报告。正式发布仍关闭。

本阶段的任务应按依赖先后实施；同一角色可兼任，但复核不能省略。所有 target_files 均为待开发应用产物，不表示本设计包已提供对应实现。

### 32.1 M2-01｜从单题扩展到不可静默变更的整卷蓝图

**负责人 / 复核：** agent / subject_lead。**依赖：** M1-09。

**先读现有材料：** `skills/exam-planner/SKILL.md`；`contracts/openapi.yaml`；`acceptance/fixtures/minimum-primary.json`。

**具体实施：**

1. 根据确认后的 exam-spec 生成五个叶子槽位：单选 2×3 分、填空 2×2 分、解答 1×10 分；知识点分值不重复归属，总计 2000 个百分分单位。
2. 程序检查槽位总数、类型、分值和课程范围；任何约束不可同时满足，先返回具体冲突。模型不能自行减少题数或扩大已教学范围。
3. 保存 plan_id、plan_hash、spec_revision 和 slot_id；前端通过新增 current-plan 接口读取并确认，只有匹配的最新计划才能生成。
4. 创建生成阶段任务按槽位或共享材料组调度；保持原顺序和稳定编号，失败只重做相应槽位，不整卷重跑。

**应交付的应用文件：** `services/api/domain/plans.py`；`services/worker/plan_tasks.py`；`apps/web/src/pages/PlanReview.tsx`。

**验证与通过证据：** 1）改变范围/总分后原蓝图确认失效；旧 generation 请求 412/409，不混用两个规格。 2）三学段生成各五题；材料父节点将来只计叶子分值，先用单测锁定规则。

**失败时处理：** 蓝图不合法时进入需修改状态，保留冲突详情并停止计费命题；不要用随机补题凑够分数。

**关联验收：** MIN-02、MIN-03、FULL-03、FULL-10。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 32.2 M2-02｜实现真正的盲解输入与运行隔离

**负责人 / 复核：** agent / security。**依赖：** M2-01。

**先读现有材料：** `contracts/blind-input.schema.json`；`contracts/public-question.schema.json`；`skills/blind-solver/SKILL.md`。

**具体实施：**

1. 由可信后端按白名单构造最终题面、选项、必要材料与资产；不包含答案、解析、评分点和作者会话。非必要 provenance 也不传给盲解。
2. 作者与 solver 使用不同运行实例/用户权限、HOME、工作目录、会话库、临时文件和范围化工具凭据。不要把业务数据库、对象存储全局密钥或 Docker socket 挂到 Agent 内。
3. 禁用回读历史和检索原题的工具；将 solver 的输出按独立 schema 校验，保存 input_hash 与独立解答。比较前不能给它作者答案纠偏。
4. 输出一致仍标记 SAME_MODEL；独立解答是证据之一，不是正确性证明。开放题比较任务、合理答案与评分依据，不能对自由文本做字符串相等判对错。

**应交付的应用文件：** `services/api/domain/public_projection.py`；`services/hermes_adapter/blind_runtime.py`；`tests/security/test_blind_isolation.py`。

**验证与通过证据：** 1）在作者文件、共享材料私有字段、日志及工具返回中放测试秘密；验证 solver 访问被拒绝，且输入白名单不含私有字段。 2）修改图或题干后 blind_input_hash 改变，必须重新盲解；只改答案仍需重新比较与审核。

**失败时处理：** 任何答案可达路径视为隔离失败，停止可用性标记；清理受污染会话并从公共输入重新跑，不能只删除最后一行。

**关联验收：** MIN-06、MIN-N07、FULL-05、FULL-20。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 32.3 M2-03｜实现确定性检查器与可信证据写入

**负责人 / 复核：** backend / subject_lead。**依赖：** M2-02。

**先读现有材料：** `contracts/validation-record.schema.json`；`reference_code/publish_gate.py`；`configs/business-policy.example.yaml`。

**具体实施：**

1. 先完成结构、叶子分值、答案选项引用、评分点合计、材料资产完整性；这些规则独立于模型，不问“AI 是否认为总分正确”。
2. 数学工具只接受受限 AST：整数/有理数、变量、批准运算和关系；控制深度、节点数和计算时限，再调用 SymPy。禁止 eval、直接执行模型代码或未经处理的任意 sympify 输入。[S13]
3. 覆盖 M2 样例的计算重算、一次方程代入/解集、基本集合与不等式边界；不支持的题面解析或复杂证明返回 REVIEW，不能用随机测试当完整证明。
4. 检查服务用独立身份写入 check_id、checker_version、content_hash、输入范围、PASS/FAIL/REVIEW 和证据。Agent 只能拿只读结果，不能自己写 PASS 或署名。
5. 对自然语言到 AST 的一致性另设审查项；数学内部公式正确不等于最终题面表达正确。

**应交付的应用文件：** `services/validators/structure.py`；`services/validators/scoring.py`；`services/validators/math_ast.py`；`services/validators/evidence.py`。

**验证与通过证据：** 1）用已知错答案、等价选项、分母为零、评分点缺失和超大表达式作控制组；记录检测与误拦。 2）检查器超时/进程失败/不支持均不能返回 PASS；伪造证据来源被后端拒绝。

**失败时处理：** 检查器错误与题目错误分开编码；检查器 bug 修复版本后重跑所有受影响题，不能让教师直接忽略真实 FAIL。

**关联验收：** MIN-06、MIN-N04、FULL-06、FULL-21、FULL-22。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 32.4 M2-04｜将错误反馈转成有上限的修订循环

**负责人 / 复核：** agent / backend。**依赖：** M2-03。

**先读现有材料：** `skills/question-author/SKILL.md`；`skills/question-reviewer/SKILL.md`；`configs/business-policy.example.yaml`。

**具体实施：**

1. reviewer 汇总独立答案与工具证据，按可定位错误提出修订；输入包含当前 revision 和约束，不允许修改原定总分与知识范围。
2. 后端原子递增 repair_attempt，默认最多两轮；Hermes 执行修订行为。每次修订创建新版本，随后重做相关盲解、工具检查和整卷影响检查。
3. 网络重试、格式修复和内容修订分别记数，统一受预算与截止时间约束；Agent 请求增加预算只产生提示，不能自己批准。
4. 超限、结果冲突未解或必要条件不充分时进入待人工复核，保留最后候选与问题。失败题不计为可用题，也不从分母消失。

**应交付的应用文件：** `services/worker/repair_tasks.py`；`services/api/domain/repair_policy.py`。

**验证与通过证据：** 1）受控注入错误触发修订并明确标 injected；验证两轮后停止；每次有新 hash 与新检查。 2）模拟并发两个修订请求，只有一个拿到该槽位的合法修订令牌，迟到结果不能覆盖新版本。

**失败时处理：** 不通过就退回修改/替换或教师调整并重确认蓝图；不能多数投票强行通过，也不无限重试直到随机正确。

**关联验收：** MIN-07、MIN-N03、MIN-N04、FULL-07、FULL-17。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 32.5 M2-05｜实现编辑、单题重生成与并发保护

**负责人 / 复核：** frontend / backend。**依赖：** M2-01、M2-04。

**先读现有材料：** `contracts/openapi.yaml`；`contracts/candidate.schema.json`。

**具体实施：**

1. 编辑器分别编辑公共题面、选项、私有答案和评分；保存发送完整候选与 If-Match，后端再校验，禁止依赖客户端隐藏字段做权限。
2. 保存创建新 revision；公共题面/材料变化使盲解和所有语义检查失效，答案/评分变化使比较、评分和审批失效；保守做法是所有相关检查重跑。
3. 单题重生成保留 slot 的目标/题型/分值，其他题保持不变；收到结果时再比较期望版本，不符合则记录 stale，不覆盖老师的编辑。
4. 共享材料编辑将所有引用子题列入受影响集合；调整顺序或打乱选项只改变显示映射，答案使用稳定 option_id。

**应交付的应用文件：** `apps/web/src/pages/ExamEditor.tsx`；`services/api/domain/revisions.py`；`services/worker/regenerate.py`。

**验证与通过证据：** 1）两浏览器同时修改同一题，一个成功一个返回冲突；页面提示差异，不 last-write-wins 静默覆盖。 2）编辑后旧证据与旧审批不能复用；单题重生不会重跑整卷或更改其他题。

**失败时处理：** 冲突时保留本地未提交草稿并让教师选择重新读取/合并；不能自动接受旧模型结果。

**关联验收：** MIN-08、MIN-09、MIN-N05、FULL-09。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 32.7 M2-07｜实现真实草稿 PDF 与 JSON 导出

**负责人 / 复核：** frontend / qa。**依赖：** M2-06。

**先读现有材料：** `docs/03_接口与开发契约.md`；`contracts/openapi.yaml`。

**具体实施：**

1. 渲染器只接收授权快照的 student 或 teacher 投影；学生对象根本不含私有答案。KaTeX 只排数学公式，HTML/CSS 定义 A4、题号、答题区和分页。[S14]
2. 固定字体、KaTeX、Chromium 和模板版本。等待 document.fonts.ready、必要图片完成和受控公式渲染结束，再调用 Playwright page.pdf；不是 sleep 固定秒数。[S34]
3. 默认阻断非白名单网络资源，图形走受控结构化绘图而非任意 SVG 脚本；对长题允许合理跨页，不给整道超页题强行 break-inside:avoid 造成溢出。

5. 逐页预检缺图、公式失败、题号/答案映射、空白页、裁切和私有字段；失败状态不得提供“最终完成”下载按钮。

**应交付的应用文件：** `services/renderer/templates/exam.html`；`services/renderer/pdf.py`；`services/renderer/projection.py`；`services/renderer/preflight.py`。

**验证与通过证据：** 1）三学段各导出可打开真实文件；核对同一 snapshot/hash、20 分、5 题、学生版无私有答案。 2）故意断开图片/字体/公式渲染，确认失败或显著阻断，不静默印出“如图”却无图。

**失败时处理：** 渲染失败只重试同一快照的渲染，不重新命题；保存错误和版本；未预检通过的文件只能受限诊断查看。
