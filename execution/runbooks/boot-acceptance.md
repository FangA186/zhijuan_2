# G-BOOT 独立验收执行单（M1，待应用实现后执行）

这不是本 ZIP 的运行说明。当前没有 apps/web 或真实 Adapter；下面检验的是未来应用交付。执行人应不是该模块实现者。

1. 从应用源码新建工作目录；记录 commit、操作系统和依赖锁。检查 README 列出每个启动命令的工作目录与变量，命令不能引用不存在的文件。
2. 在服务端配置测试凭据；启动数据服务，执行真实迁移，启动 Hermes、Worker、API 与 Web。逐项核对 health/readiness，不能仅看容器 running。
3. 读取当前身份与能力，建立小学、初中、高中各一份配置；M1 可各一题，题数/分值/方法要求需由执行者现场确认。
4. 发起规划，通过 current-plan 读取逐槽目标并确认。提交 generation 后取得 job_id；核对实际 Hermes run 和 DeepSeek 路线。
5. 回读结构化候选、答案和解析；刷新页面仍存在。数据来自当前真实任务，不能硬编码、随机模板或绕过 Hermes。
6. 缺 Key、无效 Key、Hermes 不可用、规格矛盾分别测试；要求明确失败、没有假题、日志不泄露凭据。计费故障注入须注明，不混为供应商真实故障。
7. 保存三学段输出、调用链、启动记录、命令退出码和缺陷。由接收者在新环境至少复现关键流程。
8. 签署 G-BOOT 后才可称“真实接入骨架”。不代表独立审题、教学质量、正式发布或完整 MVP 已通过。
