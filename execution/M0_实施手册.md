## 30 M0 执行：范围、工程与 Hermes 能力准备

进入条件：产品方向已确认；实际源码尚可不存在。退出产物：签署范围/责任/参数、可重复上游来源及能力探测报告。G-PREP 通过不等于应用能运行。

本阶段的任务应按依赖先后实施；同一角色可兼任，但复核不能省略。所有 target_files 均为待开发应用产物，不表示本设计包已提供对应实现。

### 30.1 M0-01｜冻结承诺范围与用途，而不是填写“支持全部”

**负责人 / 复核：** product / subject_lead。**依赖：** 无，先冻结需求。

**先读现有材料：** `acceptance/capability-matrix.template.yaml`；`configs/business-policy.example.yaml`。

**具体实施：**

1. 逐项登记小学、初中、高中的首发学科、题型、课程范围及输出格式；三个学段不可删，具体学科和题型由产品与教研共同签名。记录每项是可生成、需人工复核，还是未支持。
2. 将“题干来源为原创生成”“历史仅恢复不检索”“网页版”“DeepSeek + Hermes”写成不可静默更改的约束。不得把 15 道数学测试题解释为最终只支持数学。
3. 区分开发演示、教师练习草稿、正式用途三种权限。M1/M2 不暴露正式发布入口；发布策略需在适用范围审查后确认，不从模型自行推断政策。
4. 列出明确非目标：题库、RAG、学生端考试、支付、自动批改、微调、全国所有教材精确映射。未签署的教材对应关系不允许 AI 自动补成事实。

**应交付的应用文件：** `docs/launch-scope.yaml`；`docs/decisions/001-scope.md`。

**验证与通过证据：** 1）检查范围文件三个学段齐全；每个承诺组合均有负责教师、检查方式与验收用例链接。 2）用一个未承诺的听力或实作请求，核对产品应禁用或显示有边界的文字草稿，不冒充完整能力。

**失败时处理：** 范围未签署时，不开 M1 联调验收；允许先做独立技术验证，不允许宣传产品已经支持该范围。

**关联验收：** FULL-02、FULL-08、FULL-27。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 30.2 M0-02｜建立责任、环境与秘密信息清单

**负责人 / 复核：** tech_lead / security。**依赖：** M0-01。

**先读现有材料：** `configs/deepseek.env.example`；`infra/README.md`。

**具体实施：**

1. 把 product、frontend、backend、agent、qa、subject_lead、ops、security 映射到实际负责人；可兼任开发角色，但必要审核分离仍按范围策略执行。
2. 为开发、验收、受控试用建立分离的配置、数据库和凭据。DeepSeek API Key 与 Hermes API_SERVER_KEY 是两种密钥；前者访问模型，后者保护内部 Agent 接口，不得混用。
3. 先批准单次真实测试预算、允许的模型和网络目的地。密钥通过服务端秘密配置注入；gitignore 覆盖 .env、运行目录、模型原始日志及生成文件。
4. 选定一个可重复的开发操作系统和 Python 3.12 基线；Node、数据库、队列与浏览器版本由安装实测后精确锁定。普通开发机即可起步，不因 Agent 自动购买 GPU。

**应交付的应用文件：** `docs/owners.yaml`；`.env.example`；`.gitignore`；`docs/environments.md`。

**验证与通过证据：** 1）在干净副本中确认只有占位变量，扫描前端构建与 ZIP 没有凭据。 2）缺模型密钥时配置检查报明确失败；有密钥只说明配置存在，不把它当成功调用证明。

**失败时处理：** 发现密钥进仓库或日志：先吊销轮换，再清除泄露产物并复测；不得只删当前文件继续使用旧密钥。

**关联验收：** MIN-N01、FULL-23、FULL-24。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 30.3 M0-03｜将现有附件转成工程基线与变更规则

**负责人 / 复核：** backend / tech_lead。**依赖：** M0-01、M0-02。

**先读现有材料：** `contracts/openapi.yaml`；`database/001_schema_draft.sql`；`reference_code/adapter_contract.py`。

**具体实施：**

1. 建立实际应用仓库，不把本文档 ZIP 原样改名为源码。按第 15 章建立 web、api、worker、hermes_adapter、validators、renderer 目录，先允许模块化单仓，不要求每目录都是独立微服务。
2. 复制并评审现有 JSON Schema、API、Skills 和 SQL 草案。将 SQL 转成可执行迁移；明确 reference_code 为参考逻辑，不当作鉴权或数据库实现。
3. 采用本轮补齐的“当前蓝图读取、规格读取、历史列表、当前身份、撤回”契约；用 execution/api-task-map.yaml 明确每个 API 的阶段与负责任务。
4. 给所有文件标记 IMPLEMENTED / TEMPLATE / CONTRACT / PLANNED。接口或 schema 变化必须同时改文档、调用端和测试；确认错误码、分值单位、ETag 和哈希边界。

**应交付的应用文件：** `pyproject.toml`；`apps/web/package.json`；`docs/contracts-map.yaml`；`docs/decisions/002-architecture.md`。

**验证与通过证据：** 1）运行本包离线校验；确认本轮 25 个业务操作都有对应开发任务，且不是调用 Hermes 的同名 /v1 接口。 2）代码评审拒绝将 Protocol 的省略号、静态 HTML 或数据库 Compose 标成业务功能已实现。

**失败时处理：** 契约存在歧义先提交变更记录，前后端共同确认再编码；不得各自猜测字段后通过临时字典绕过校验。

**关联验收：** MIN-02、MIN-03、FULL-03、FULL-28。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 30.4 M0-04｜获取固定 Hermes 来源并制作可重复安装记录

**负责人 / 复核：** agent / ops。**依赖：** M0-02。

**先读现有材料：** `docs/06_DeepSeek_Hermes接入指南.md`；`configs/hermes-reviewed-fragment.yaml`。

**具体实施：**

1. 从官方仓库选择候选提交，记录完整 40 位 commit 与来源；不是直接长期追踪 main。本章命令给出克隆与固定步骤，但实际提交须开发者审查，不在本设计包伪造一个“已验收版本”。
2. 在隔离开发环境按该提交的安装说明和锁文件安装；保留完整命令、退出码、系统与依赖版本。上游安装脚本先审阅再运行，不要求普通教师安装 Hermes。
3. 记录 git rev-parse HEAD、工作区是否修改、LICENSE 摘要和依赖锁哈希。选择子模块或锁定获取脚本二者之一；代码包缺 .git 时仍需保留可复现来源记录。
4. 将业务服务和 Hermes 的依赖环境分离，避免上游升级影响 FastAPI 业务进程；检查 core、API、所需 MCP 依赖即可，不无差别启用全部第三方工具。

**应交付的应用文件：** `install/hermes-source.lock.json`；`install/hermes-install.sh`；`vendor/hermes-agent`；`docs/runtime-baseline.md`。

**验证与通过证据：** 1）第二个干净环境能取回相同提交；本地版本来自运行目录，不是从配置复制。 2）验证命令帮助、安装日志和原生 API 启动入口；依赖冲突必须被记录，不自行取消锁定以求“能启动”。

**失败时处理：** 候选提交无法安装时，记录失败并另选提交重新审查；不得静默退到另一框架或绕开 Hermes。

**关联验收：** MIN-01、FULL-01、FULL-04。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 30.5 M0-05｜先做 Hermes 能力与安全验证，再确定接入细节

**负责人 / 复核：** agent / security。**依赖：** M0-03、M0-04。

**先读现有材料：** `execution/templates/hermes-capability-probe.yaml`；`reference_code/adapter_contract.py`；`configs/business-policy.example.yaml`。

**具体实施：**

1. 默认验证服务器内部 HTTP Runs 接入：能力查询、创建 run、状态、事件、stop；记录真实请求与响应字段。官方文档有接口不等于候选提交已支持，逐项实测。[S28][S29]
2. 验证能限定 DeepSeek、禁用长期记忆和不必要工具、加载指定 Skill、获得结果和用量；对无法强制的每次调用预算明确写“不支持”，由外部截止和预算预留兜底，不能发明原生参数。
3. 验证新 run 不继承其他任务历史；将命题与盲解的 HOME、会话库、工作目录、临时文件和工具凭据分开。只换 session_id 或 git worktree 不是文件访问隔离。[S04]
4. 若 HTTP 模式无法兑现工具白名单或隔离，先阻断；通过架构决策切换为同一 Hermes 的受控 Python 子进程适配，并保留相同业务协议。两种接入只选一种生产实现，不额外引入 LangGraph。
5. 单次无敏感信息模型测试由预算负责人授权；记录真实 provider/model 与辅助调用目的地。不接受 model=hermes-agent 响应标签作为实际 DeepSeek 型号的唯一证据。

**应交付的应用文件：** `docs/hermes-capability-report.yaml`；`docs/decisions/003-hermes-transport.md`。

**验证与通过证据：** 1）填写能力探测表，核心项必须有实测证据或明确阻断；不得把 UNKNOWN 填成 PASS。 2）盲解试图读取作者区秘密文件应被工具/操作系统拒绝；不仅检查最后答案有没有泄露标记。

**失败时处理：** 核心能力不满足则 G-PREP 不通过。保留备选路径与影响范围，再做隔离验证，不先建设大量页面假装技术风险不存在。

**关联验收：** MIN-04、MIN-06、FULL-05、FULL-21、FULL-22。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 30.6 M0-06｜冻结测试预算、质量口径与阶段门

**负责人 / 复核：** qa / product。**依赖：** M0-01、M0-03、M0-05。

**先读现有材料：** `acceptance/mvp-plan.yaml`；`acceptance/minimum-cases.yaml`；`acceptance/full-cases.yaml`。

**具体实施：**

1. 把 M1 接入、M2 功能、M3 教学质量分成三个结果。M1 三学段各一题不证明质量，M2 各五题只验证链路，M3 才执行分层盲评。
2. 明确首轮可用率、完整交付率、严重错误漏放和 REVIEW 的分母；80%/90% 是旧版建议起点，不是行业标准。未确认质量阈值不得在测试后按结果调低。
3. 在首个正式评分运行前固定模型候选、Skill、测试配置和预算。允许先做明确标记的试探测试修正规则，但试探样本不得混入后续验收分数。
4. 把每条任务负责人、输入、依赖、产物、失败处理登记到执行索引；批准 G-PREP 后进入 M1。代码实现和模型运行证据保持空白，不能因为文档检查通过改状态。

**应交付的应用文件：** `acceptance-runs/parameters.yaml`；`docs/signoffs/G-PREP.md`。

**验证与通过证据：** 1）审批表包含实际人员、日期和参数版本；所有必测项有负责人，无孤立能力项。 2）演示 NOT_RUN、BLOCKED、FAIL 都不能判定阶段通过；不允许删除失败用例以过关。

**失败时处理：** 任何关键阈值、负责人或首发范围缺失，则停留准备阶段；只开展独立技术试验，不签 M1/M2 已验收。

**关联验收：** MIN-12、FULL-25、FULL-27、FULL-28。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。
