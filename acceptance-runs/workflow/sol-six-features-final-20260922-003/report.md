## 行为影响与兼容范围

- 前端启动流程现在必须先预览并确认蓝图；刷新只读当前任务。POST 结果未知时先 GET 对账，不能直接重新提交可能计费的请求。
- 同规格任务运行时重拟蓝图会被服务端拒绝，需先取消或等待原任务结束；事务锁下的二次核对阻止“先读旧蓝图、稍后创建任务”的竞态。重新规划后旧候选、检查和审批不会冒充新方案结果，历史数据保留。
- `database/003_generation_jobs.sql` 和 `004_generation_exam_state.sql` 为本地单份 `current` 草稿及队列状态提供持久化。本轮只在专属测试数据库执行；没有实施正式租户/RLS/Alembic 迁移，也没有修改冻结的原始 32 项任务基线。
- 原同步单题重生成没有可靠的版本/账单闭环，现明确拒绝，等待 M2-05 的版本化单题任务。正式发布接口返回 501，避免发布旧内存题目或编造渲染产物哈希。对应任务仍进行中。
- 检查不再自动把缺失答案补成 A、不截断分值、不丢弃表格/资源块来迎合契约；非法模型结果失败。命题结果已确定 FAIL 时不再发起盲解收费请求。
- 费用代理批准依据与用途见 [DEV-004](../../../docs/decisions/DEV-004-live-budget-proxy-proposal.md)，只用于本轮受控验收；未扩展成生产出口。
- 不含题库、RAG、其他 Agent 框架。命题/盲解输入不包含开发记忆或验收答案。

## 开发记忆的使用方式

每个实质检查点保留新交接，填写 completed、pending、decisions、failed_approaches 和 evidence_refs。完成开发后更新 `features.yaml`、`work.yaml`，生成 `current.md`，再运行 `finish --task <任务ID>`。它能发现遗漏和过期记录并返回非零，但不能自动知道开发事实或证明审核人身份。

本轮最终记录以 [closeout-final.json](closeout-final.json)、当前摘要及产品任务 `astra-closeout-20260922-003` / 开发记忆 `astra-closeout-20260922-004` 交接为准；旧 Sol 交接保留为历史证据，不覆盖或伪造原来的验证范围。最初收尾发现时区问题的 FAIL 记录保留在 `closeout.json`。
