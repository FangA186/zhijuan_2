# 现场验收演示脚本（待实现后执行）

**不是当前包的一键启动说明。**应用启动命令必须由实际工程提供并在新环境验证，不能将只启动 PostgreSQL/RabbitMQ 当应用已启动。

## 演示 A：最小闭环 G-MIN

由接收者按工程 README 启动服务，读取真实 health/版本与模型配置；缺密钥时先展示明确错误。填写当前 fixture 的课程范围，教师确认后将 scope_confirmed 置 true，先演示小学，随后完整重复初中和高中。

现场改一项未预置的知识点或方法限制；检查蓝图 5 题 20 分并确认。观察真实任务编号、Hermes/DeepSeek 调用和逐题进度。刷新页面，不重新触发生成。查看独立解题和实际检查；受控注入一次分值或答案错误，展示有限修订与待审状态。

编辑一题并保存，展示旧检查过期；重新生成一题，验证其他题不变。保存、关闭并重开。教师确认后下载有标识的学生／教师草稿 PDF 和 JSON，核对版本、题号、公式、分值与答案隔离。按 MIN-N01—MIN-N07 执行失败场景并归档。

## 演示 B：完整闭环 G-FULL

使用已批准的完整规格，三学段各演示数学卷与材料／开放题卷，并补齐首发能力组合。展示作者、盲解、审核角色及文件权限区别，检查器的 FAIL/REVIEW 与教师裁决不能混淆。

展示共享材料修改后的关联重检、并发编辑冲突、有限修订和整卷检查。先提交审核，再生成受限最终产物；批准真实文件哈希后下载同一字节文件。修改模板或题干后复用旧审批必须失败。打开 PDF 和可编辑 Word；检查学生 API/HTML/PDF 无私有答案。

在测试环境演示至少一次重复消息、崩溃恢复、断线、取消迟到、预算不足和模型故障。执行跨组织、提示注入与只读规则测试。演示撤回、更正、备份恢复和审计查询。

## 证据与结论

实际结果写入独立 acceptance-runs 目录；使用 manifest 和报告模板。供应商未提供 request_id 时记录替代可追踪证据，不编造 ID。故障注入不算模型真实错误率，mock 不算成功接入。质量统计按阶段/学科/题型分别报告。

接收者独立操作后，根据必测用例、版本、缺陷和签字判定。任何必需项未测或无证据，不能宣称整个 MVP 已验收。
