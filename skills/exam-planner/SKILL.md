# exam-planner

本项目技能模板，须在固定 Hermes 版本与工具权限下集成验证。

## 输入
ExamSpec、学段／学科规则、用途策略与预算约束。

## 输出
每个槽位的题型、分值、知识点、能力、难度倾向、材料依赖；冲突清单。

## 执行流程
1. 先确认范围字段与用户目标一致，不自行推定未知教材章节。
2. 按照题型和分值创建槽位；跨知识点分值只分配一次。
3. 调用结构检查，报告不可能同时满足的要求，不暗中改配置。
4. 对材料题规划共享材料与子题依赖；区分客观题和开放题的评分方式。
5. 只提交计划，最终确认与任务启动由业务后端决定。

## 失败与权限边界
工具不可用、输入矛盾、证据不足时明确返回错误或待复核。不得编造工具结果、扩大权限、修改规则或输出私有思维链。只提交简洁可审核依据。任务目录与工具权限由后端实施，技能文字本身不提供隔离。

## 本版执行约束

本 Skill 由 Hermes 执行，默认使用 DeepSeek；不调用或安装 LangChain、LangGraph。模型、阶段、题目版本、工具权限和修订额度来自后端批准的配置，不能由 Skill 自行扩大。角色使用同一 model_id 时标记 SAME_MODEL，不声明异构验证；无法确认时返回待复核，不变更审批与发布条件。

## 生产蓝图设计（blueprint-design 契约）
输入 spec 是教师批准的范围、考试用途、题型数量与分值；slots 仅为不可改动的结构骨架，不是示范答案。difficulty_quotas 是整卷难度题数。严格返回 output_schema 中的 summary、conflicts、slots，不输出完整试题或答案。

- 先分析考试用途、学段、教材与范围，设计章节覆盖、认知能力、题型适配和由易到难的梯度，在 summary 说明分配理由及主要内容覆盖；没有教师权重时明确这是建议分配，不能声称来自官方考试权重。
- 每个输入 slot_id 恰好输出一次。题型与分值由后端保留，不得变更。difficulty 的总数量必须符合配额；在各题型内安排梯度，不能简单按全卷前后切段。
- knowledge_ids 选择该槽位 section_id 对应 topics 中的1至4个具体考点。主要考点可合理复现，但组合、情境和解题任务须有区别；不可把每条目录机械轮换一次当整卷规划。
- 章节标题、小结、阅读与思考、探究与发现、信息技术应用、数学建模栏目只作背景；不得直接作为 knowledge_ids。将综合能力落实到范围内具体知识点；不得扩展范围以满足题数。
- design_brief 写可供命题Agent执行的具体题目设计：考查任务、建议情境/条件形式、关键推理路径或干扰项目标；不提前给出答案，不重复同一方程、条件和任务。
- cognitive_target 写本题能力目标；rationale 写与题型、分值、难度的匹配依据。综合题可组合多个已授考点；短小客观题不塞入过长建模任务。
- 输入矛盾或没有足够具体考点时在 conflicts 中明确列出，不能编造考点或偷偷修改配置。外部服务失败不生成伪蓝图。

输出要精炼以适配现有输出预算：summary约150字，每题design_brief约30字、rationale约15字、cognitive_target约6字；保持含义可执行，不能为省字遗漏槽位。不得自行提高token或调用预算。
