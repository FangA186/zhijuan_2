### 29.2 唯一执行入口和文档层级

阅读顺序：本章→第 30—33 章对应阶段→第 34 章命令/API→第 35 章验证与签收；按需回查 01—23 的产品/架构细节和 24—28 的验收定义。ZIP 的 `execution/task-index.yaml` 是任务编号、依赖和输入/产出索引；`acceptance/` 是测试动作，不是任务状态机。

`source_files` 指当前包里已存在的材料，`target_files` 指未来应用中要新增或修改的文件，两者不能混淆。每张任务卡至少写明负责人、复核人、前置任务、输入、实施步骤、目标文件、验证、失败处理与验收映射。角色名称在 M0-02 绑定具体人员；不能整张卡写“团队负责”。

任务状态用 NOT_STARTED / IN_PROGRESS / BLOCKED / DONE；运行验收仍用 NOT_RUN / PASS / FAIL 等。任务 DONE 必须有真实代码/配置和测试证据，阶段通过还需单独签收；没有应用不能把 32 张任务卡填 DONE。

### 29.3 不以迎合替代技术判断

DeepSeek + Hermes 是既定路线，不等于一安装就具备教育正确性、强隔离和完整 SaaS 权限。先验证接口、工具限制、盲解环境与费用可观测；不能为了保住图纸中的一个盒子而隐瞒失败。默认使用受控 HTTP Runs；确实不适配时，以书面决策改为同一 Hermes 的隔离 Python 运行，不叠加第二套 Agent 编排器。

Celery 只负责投递和恢复，Hermes 负责 Agent 循环；后端保存不可变业务事实、预算和发布。当前仅受控草稿验证，普通网页用户不能直连全权限 Hermes 管理端。一个模块一个明确负责者，不要求每个模块一台服务器。

### 29.4 先后与可并行范围

M0 先冻范围/责任，再核查 Hermes 实际能力。M1 先业务入口/数据库与 Adapter，随后队列/API，最后接网页与真实日志。M2 先蓝图→盲解→检查→修订，再编辑/审核/导出和失败测试。M3 学科完善、身份、恢复可以并行；完整审批、最终文件和质量签收必须等依赖全部完成。

API 静态契约和网页布局可提前并行，但必须标 mock；真实接入与权限测试不能被 mock 替代。详情按每张卡 depends_on 执行，新增依赖要改索引并重跑离线依赖检查。

### 31.1 M1-01｜实现业务服务入口、配置和健康检查

**负责人 / 复核：** backend / ops。**依赖：** M0-06。

**先读现有材料：** `configs/business-policy.example.yaml`；`configs/deepseek.env.example`。

**具体实施：**

1. 创建 FastAPI app 与环境配置校验。区分 liveness（进程活着）、readiness（关键依赖可用）和模型实调用探测（可能计费），健康检查不反复调用模型。
2. 默认网页只访问业务 API；Hermes API、数据库和队列不向公网开放。设置请求体限制、统一错误体、trace_id，响应和日志不输出密钥。
3. 实现本地开发身份开关：只能监听回环或受控验收网；生产启动检测到 dev-auth 必须失败。不得信任浏览器直接传来的 tenant_id 或角色。

**先读现有材料：** `contracts/blind-input.schema.json`；`contracts/public-question.schema.json`；`skills/blind-solver/SKILL.md`。

**具体实施：**

1. 由可信后端按白名单构造最终题面、选项、必要材料与资产；不包含答案、解析、评分点和作者会话。非必要 provenance 也不传给盲解。
2. 作者与 solver 使用不同运行实例/用户权限、HOME、工作目录、会话库、临时文件和范围化工具凭据。不要把业务数据库、对象存储全局密钥或 Docker socket 挂到 Agent 内。
3. 禁用回读历史和检索原题的工具；将 solver 的输出按独立 schema 校验，保存 input_hash 与独立解答。比较前不能给它作者答案纠偏。
4. 输出一致仍标记 SAME_MODEL；独立解答是证据之一，不是正确性证明。开放题比较任务、合理答案与评分依据，不能对自由文本做字符串相等判对错。

**应交付的应用文件：** `services/api/domain/public_projection.py`；`services/hermes_adapter/blind_runtime.py`；`tests/security/test_blind_isolation.py`。

**验证与通过证据：** 1）在作者文件、共享材料私有字段、日志及工具返回中放测试秘密；验证 solver 访问被拒绝，且输入白名单不含私有字段。 2）修改图或题干后 blind_input_hash 改变，必须重新盲解；只改答案仍需重新比较与审核。

**失败时处理：** 任何答案可达路径视为隔离失败，停止可用性标记；清理受污染会话并从公共输入重新跑，不能只删除最后一行。

**关联验收：** MIN-06、MIN-N07、FULL-05、FULL-20。执行记录使用 `execution/templates/task-record.md`，包含实际版本、命令退出码、断言和脱敏证据。

### 32.3 M2-03｜实现确定性检查器与可信证据写入

**负责人 / 复核：** backend / subject_lead。**依赖：** M2-02。

**先读现有材料：** `contracts/validation-record.schema.json`；`reference_code/publish_gate.py`；`configs/business-policy.example.yaml`。

**具体实施：**

2. 数学工具只接受受限 AST：整数/有理数、变量、批准运算和关系；控制深度、节点数和计算时限，再调用 SymPy。禁止 eval、直接执行模型代码或未经处理的任意 sympify 输入。[S13]

5. 对自然语言到 AST 的一致性另设审查项；数学内部公式正确不等于最终题面表达正确。

**应交付的应用文件：** `services/validators/structure.py`；`services/validators/scoring.py`；`services/validators/math_ast.py`；`services/validators/evidence.py`。

**验证与通过证据：** 1）用已知错答案、等价选项、分母为零、评分点缺失和超大表达式作控制组；记录检测与误拦。 2）检查器超时/进程失败/不支持均不能返回 PASS；伪造证据来源被后端拒绝。

**失败时处理：** 检查器错误与题目错误分开编码；检查器 bug 修复版本后重跑所有受影响题，不能让教师直接忽略真实 FAIL。

### 34.2 Hermes 源码获取与安装的具体顺序

以下在专用开发目录执行，要求 Git、Python 与经审查的依赖安装工具已存在。本轮只提供步骤，没有执行克隆/安装。先由技术负责人选择并填写真实 40 位提交，不以文档日期冒充版本。

```bash
# UPSTREAM_SETUP；在开发者新建的应用仓库目录，不在本材料 ZIP 中执行
export HERMES_COMMIT='REPLACE_WITH_REVIEWED_40_CHAR_COMMIT'
# 开始前校验变量已替换，未替换必须退出
printf '%s' "$HERMES_COMMIT" | grep -Eq '^[0-9a-f]{40}$' || exit 2
mkdir -p vendor
git clone --no-checkout https://github.com/NousResearch/hermes-agent.git vendor/hermes-agent
git -C vendor/hermes-agent checkout --detach "$HERMES_COMMIT"
git -C vendor/hermes-agent rev-parse HEAD
git -C vendor/hermes-agent status --porcelain
```

git clone 会联网下载，上述目录必须不存在；已有目录先核查来源与工作区，不用 rm -rf 覆盖。提交来自批准锁定记录，克隆成功只说明源码存在。然后在源码外建立 venv，按该提交文档和锁文件安装，检查安装输出。官方开发说明有独立 venv 和源码安装路径；本项目不要求照搬 all/dev 全量可选依赖。[S30][S31]

业务依赖与 Hermes 使用不同 venv/镜像。安装命令必须由开发负责人根据固定提交实际验证，并写入 install/hermes-install.sh 及运行报告；不能凭当前在线文档保证一个未测依赖组合。若使用 uv.lock，使用与提交匹配的冻结安装方式；若缺可重复锁，则先生成审定 lock 再交付，不只保存 pip freeze 当完整可重复构建保证。

### 34.3 配置和启动原生服务

在独立的受控测试 HOME/runtime 内配置 provider=deepseek 和已验证 model_id；DEEPSEEK_API_KEY 从服务端秘密配置注入。原生 API 另需 API_SERVER_KEY，不能使用模型密钥替代。[S27][S29]

```text
# UPSTREAM_SETUP；变量名称已核查，真实值不写入本文件
API_SERVER_ENABLED=true
API_SERVER_HOST=127.0.0.1
API_SERVER_PORT=8642
API_SERVER_KEY=<server-only-secret-reference>
DEEPSEEK_API_KEY=<server-only-secret-reference>
```

在已激活的正确 Hermes 环境执行 `hermes model` 配置 DeepSeek，再执行 `hermes gateway` 启动 API。[S29] 对容器部署，容器内监听地址与宿主暴露策略分别控制，默认只在受控网络可达；不要为方便把管理端口公开。

服务端调用原生 `/health` 看存活，`/health/detailed` 读取状态字段而不只看 HTTP 200；它不能证明模型已可用。`/v1/capabilities`、`/v1/skills`、`/v1/toolsets` 按固定版本支持情况探测。API 原生默认能力较宽，业务必须在接收不可信教师输入前落实工具白名单；“提示里说禁止”不是权限控制。[S29]

### 34.4 原生 Runs 映射：这是开发契约，不是 SDK 包装已实现

| 原生操作（Hermes 内部服务） | Adapter 应执行什么 | 明确禁止 |
| --- | --- | --- |
| POST /v1/runs | 使用批准的 model/provider、单次 input 和指定 Skill 指令；保存 run_id；仅在实测支持时使用幂等键 | 复用作者 previous_response_id 给盲解；信任客户端 provider |
| GET /v1/runs/{id} | 检查实际终态与 completed/partial/error；结构校验后才保存成功 | HTTP 200 就算命题成功 |
| GET /v1/runs/{id}/events | 消费事件、脱敏并持久化必要业务事件；接受重复/重连 | 全量转发答案、工具 preview、私有推理 |
| POST /v1/runs/{id}/stop | 请求合作停止，业务先禁止派发/写回，查最终退出 | stop 返回即宣称所有在途费用取消 |

API 具备这些表面能力并不自动提供知卷的权限、题目版本、成本账本和发布流程。`/v1/runs` 的保留/幂等机制与候选提交绑定，不能把在线文档的缓存时限当永久保证；结果不明先对账。[S28][S29]

### 34.5 业务 API 联调的真实顺序

业务地址与 Hermes 地址分开。下面路径来自本包 `contracts/openapi.yaml`；全部是待实现业务 API。身份 cookie/CSRF 从实际身份流程取得，不在文档硬编码凭证。

```text
GET   /v1/session                         读取受信身份/权限
POST  /v1/exams                           创建已确认范围的草稿
GET   /v1/exams/{id}/spec                  恢复完整规格与 ETag
POST  /v1/exams/{id}/plan-jobs             获得 job_id
GET   /v1/jobs/{job_id}                    等规划完成
GET   /v1/exams/{id}/plans/current         获得 plan_id/hash/slots
POST  /v1/exams/{id}/plans/{plan_id}/confirm 确认指定计划
POST  /v1/exams/{id}/generation-jobs       执行真实命题
GET   /v1/jobs/{job_id}/events             读取业务进度
GET   /v1/exams/{id}?view=teacher          授权读取候选
POST  /v1/exams/{id}/validation-jobs       检查/盲解
PATCH /v1/exams/{id}/slots/{slot}/content  编辑并使旧证据失效
POST  /v1/exams/{id}/review-decisions      当前版本人工审核
POST  /v1/exams/{id}/export-jobs           M2 草稿；M3 待审最终文件
GET   /v1/exports/{export_id}              查询实际渲染与文件哈希
POST  /v1/exams/{id}/publish               仅 M3 满足全部条件
POST  /v1/exams/{id}/publications/{snapshot_id}/revoke
```

每个写请求携带契约要求的 CSRF/If-Match/幂等键，具体 body 以 OpenAPI 为准。新增读取接口返回确定形状，前端不用猜 Job 的任意 result 字段。鉴权系统登录/回调/退出为 M3-02 的身份集成工作，不把 `GET /v1/session` 当登录接口。

## 35 逐阶段交接、故障分支与证据签收

### 35.1 开发人员拿到包后的第一轮操作

先解压并阅读 README，运行本包离线命令了解已有契约，不创建假成绩。随后按 M0-01—06 建立应用仓库、填实际负责人和配置、固定 Hermes 来源并探测能力。通过 G-PREP 后，将 M1-01—09 拆为代码审查单；每单附变更文件、测试和证据。第一轮交付必须是可启动源码与真实记录，不是另一张架构图。

每次任务认领先读 source_files，再落实 target_files。提交代码时同步 OpenAPI、Schema、数据库迁移、页面和测试；目标路径可因真实工程调整，但必须更新 task-index 和 API 映射，并由技术负责人说明迁移，不能让文档指向不存在的文件。

### 35.2 阶段签收的操作顺序

| 阶段门 | 谁执行 | 执行材料 | 必须得到的证据 |
| --- | --- | --- | --- |
| G-PREP | 产品/技术/教研/安全 | M0 卡片、能力探测表、参数表 | 实际范围/角色签署，上游版本与能力报告，未知项阻断 |
| G-BOOT | 非实现者 QA 或接收人 | boot-acceptance.md | 新环境启动、三学段真实题、失败场景、实际调用链 |
| G-MIN | QA + 三学段教师 | minimum-cases.yaml、fixtures、演示脚本 | 19 类按重复规则执行，三套草稿及修订/编辑/取消证据 |
| G-FULL | QA/教研/安全/运维/产品 | full-cases.yaml、能力矩阵、签收表 | 28 类与承诺组合全覆盖，质量/权限/恢复/可编辑文件实测 |

每条验收 YAML 已细化为 4 个步骤，包含清理、预期、证据和 implementation_tasks。它们仍是待执行规程，不是已编写的 Playwright E2E 测试。用例编号未变；运行结果另存 acceptance-runs，不修改材料模板以假装已经完成。

### 35.3 失败分类、恢复与归属

| 症状 | 首先定位 | 处理路径 | 不允许的处理 |
| --- | --- | --- | --- |
| 没密钥/401 | M0-02、M1-01 | 配置前置拒绝/鉴权失败，轮换或恢复后重新授权 | 假题回退、无限重试、输出 Key |
| 创建 run 超时 | M1-03、M3-05 | RECONCILING 查询实际运行，必要时人工授权重试 | 无条件再次生成并宣称只扣一次费 |
| JSON/字段不合法 | M1-06、M2-04 | 有上限格式修复或失败，保留原错误 | 自动补一个未求证标准答案 |
| 检查超时/不支持 | M2-03 | REVIEW 或运行故障，工具恢复重检 | 直接 PASS |
| 正确性冲突 | M2-04、M3-01 | 定位依据，修订/教师复核，保留原记录 | 多数投票、改宽规则 |
| 并发覆盖/旧结果 | M2-05 | If-Match/栅栏校验，冲突后重新读取 | 覆盖教师新版本 |
| 缺图/公式裁切 | M2-07、M3-04 | 相同快照重渲染，旧审批失效 | 为了导出重生整卷 |
| 越权/答案泄露 | M3-02 | 暂停、轮换、审计和更正，安全回归 | 只删截图或隐藏字段 |
| 某学段质量不达标 | M3-06 | 分层定位，规则/模型新版本重测 | 删除该学段或事后改阈值 |

### 35.4 可交付效果必须由实际产物证明

M1：你在新环境打开网页，三学段各生成并保存真实题；失败明确。M2：教师能配置五题小卷、看到检查与问题、修改/重生成并拿到草稿 PDF/JSON。M3：在批准范围内完成完整审核、对应文件发布/撤回，接收者能够自行部署、排错和恢复。文档页数、任务卡数、离线测试数都不是这些效果的替代证据。

代码包、运行证据包和说明文档分开标识。提供准确入口、锁定版本、密钥模板、迁移和依赖说明；真实 Key 不打包。M3 输出的试卷 DOCX 与本产品方案 DOCX 是不同文件，不能拿方案文档成功渲染来证明出卷引擎已实现。

### 35.5 本轮真正增加了什么

本轮在原 v1.2 上补充 32 张开发执行卡、4 份阶段手册、命令/API 顺序、接口到任务映射、故障注入规程、能力探测/质量/签收模板，并细化原 47 类验收动作；新增 5 个业务接口草案。全部同步写入本 Word、HTML、Markdown 及 ZIP。
