# 项目进展与资料看板

在前端开发服务中打开 `http://localhost:3000/project`，或点击教师工作台顶栏的「项目进展」。无需先启动 FastAPI，不会触发出题或模型调用。开发服务未启动时，在 `apps/web` 执行 `npm run dev`；使用项目现有 `.venv` 的 PyYAML 环境。

## 五个入口

- Bug 记录：搜索症状、报错、模块和任务；筛选待处理、已修复、复发，查看根因、修复、回归与同步状态。直达 `http://localhost:3000/project?tab=bugs`；维护方式见 [Bug记忆流程](../progress/bugs/README.md)。

- 功能与迭代：按已实现、进行中、未开始筛选，查看限制、实现文件、任务、依赖和不能破坏的行为。迭代页列关联会话检查点与源码提交。
- 任务与验收：实际状态覆盖原任务模板，保留旧 DONE 被纠正的原因；查看依赖和任务要求、历史报告范围及测试数量。
- 开发规则导航：用中文解释功能账本、任务、证据、交接和自动摘要；AGENTS 中的链接与现有路径动态提取。可只读查看开放文档。
- 目录与文件：按目录浏览和筛选文件名，显示用途、说明依据与关联功能。大目录每页 150 项；没有登记的用途明确标为推断。

## 数据从哪里来

当前状态来自 `progress/features.yaml` / `work.yaml`；任务合并 `execution/task-index.yaml` 与 `progress/extra-tasks.yaml`。交接来自 `progress/handoffs/`，报告来自 `acceptance-runs/`；只有功能登记的 last_evidence 按现有工具校验证据指纹，历史 PASS 不自动成为当前 PASS。

Bug 来自 `progress/bugs/BUG-*.yaml`，Notion回读映射在同目录 `notion-sync.json`。内容变动后自动显示待同步；同步由交付代理通过 MCP 执行，不是后台双向同步。

用途说明集中维护在 `progress/file-guide.yaml`。添加文件后会自动出现在目录树；如需准确说明，在该文件的 files/directories 中登记，不用修改页面代码。右上角刷新会重读账本；目录切换会读取当前文件列表。

产品方案版本、交接包版本、前端包版本分别展示。没有独立功能版本登记时，页面只展示可关联的检查点和 Git 提交，不编造 v1/v2。检查点保留历史原意；同任务关联不保证覆盖整个功能，记录时 HEAD 也不能证明当时改动已提交。

## 可读边界

仅本机同源 Vite 开发服务启用资料接口，生产构建不提供本页入口、资料接口或仓库快照。不把项目目录授权给生产命题 Agent。

正文限开发文档白名单，所有文字按文本渲染；凭据、符号链接、上传试卷、教材图片、原始日志和一般源码不开放正文。Git 内部、依赖、缓存、虚拟环境仅展示目录用途，不展开内部文件。该页面不是生产管理员权限系统，也不执行文档里的命令。
