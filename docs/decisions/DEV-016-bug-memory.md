# DEV-016：Bug 修前检索与修复记忆

状态：ACCEPTED。2026-09-24 用户明确要求每次修Bug前扫描历史、修后记录，并接入Notion与本地项目页。

选择一条Bug一个 `progress/bugs/BUG-YYYYMMDD-NNN.yaml`；继续使用现有任务账本、交接和验收证据目录，不复制全部日志。固定ID承载复发历史，关键词检索提供线索；旧记录必须对照当前调用链与复现条件。首批DEV-03修复记录保留历史验收日期，未给它们冒填当前源码验证指纹。

开发入口AGENTS约定自动执行修前检索。`context`附相关Bug索引；`search --task`保存查询回执。`finish`对已声明Bug任务（回执、bug_ids或work_type=BUGFIX）检查查询、Bug关联与完成时的修复/同步状态，旧检查点前的检索不能替代新一轮。它不能识别所有自然语言任务或认证操作者，不保证任意外部Agent一定服从指令。

Notion通过官方MCP写入并回读，稳定ID映射存 `notion-sync.json`，内容变化标待同步。同步回执是开发流程记录，不是远端自动监听或可信签名；没有双向后台进程。Agent只上传明确编写的症状、根因、修复与证据路径，不上传密钥、原始日志或试卷正文。

迁移：保留已有Notion任务/缺陷卡，新增修复知识库和总览入口，以任务ID关联；不把历史记录升级为产品完成。验证覆盖本地查询、失效同步、门禁缺项与页面操作，Notion逐卡回读核对。
