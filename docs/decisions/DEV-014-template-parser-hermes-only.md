# DEV-014：模板结构识别不得走 DeepSeek 直连

日期：2026-09-24。状态：PROPOSED（本地缺陷修复已实施；模板 AI 能力的正式范围未签收）。

## 背景

用户在“AI 模型深度识别”处看到 `Direct provider calls are disabled; use Hermes run_stage`，页面随后用规则识别结果宣称“100% 精准识别”。源码显示模板解析器仍调用已禁用的 `_call_deepseek_chat`；成功状态仅代表规则识别出了结构，并非模型完成或人工验收。用户提供的卷面还存在“10 题、每题 4 分、共 52 分”的原文冲突。

## 本地修复选择

本版模板上传只运行确定性文字/规则提取。旧 `force_llm=true` 请求明确返回 501，页面移除不可用的“AI 模型深度识别”按钮及“100% 精准”承诺，展示原文分值冲突和待教师核对提示；无法读取的文件返回 422。

没有把模板识别塞入现有命题或盲解 Hermes 角色：它们没有模板解析契约；当前同步 HTTP 入口也不是持久计费任务。恢复 AI 深度识别需独立确定 Hermes Skill/角色、结构化结果校验、任务状态、调用标识与费用记录，再做真实验收。项目既有“生产仅经 Hermes”的不变量是这次停止直连的依据；本记录不声称用户已批准取消未来 AI 模板能力。

## 影响、迁移与回归

影响 `services/exam/template_parser.py`、模板解析 API、前端弹窗与 API 客户端。旧前端保留的 `force_llm` 请求会得到明确 501，不再收到混有模型失败文案的规则结果；普通上传仍返回题组结构。已有试卷草稿及已上传文件不自动改写。10 项模板单测、前端构建、运行态合成模板请求均通过；未发起模型请求、未重写用户模板。若恢复模型能力，不得重新启用直连 helper 或把规则结果冒充模型结果。
