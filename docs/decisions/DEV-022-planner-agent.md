# DEV-022 Hermes 规划 Agent 与持久蓝图任务

状态：ACCEPTED；日期：2026-09-29；任务 M2-01。
批准依据：用户明确要求“做一个规划agent用于设计蓝图，然后再由后面的出题agent来完成，一步到位”。

原实现用确定性轮换产生考点与难度，无法承担整卷教学设计。本次使用已有Hermes planner角色；程序仅建立不可改动的题量/题型/分值骨架与难度配额，不向模型传入规则分配的示范考点。模型提交考点组合、设计任务、能力目标、难度、依据及冲突。

采用单次有界规划调用；不新增框架或历史题库，不改变现有预算代理上限。结构化输出出口新增planner契约，防止被误当作solver响应。schema、槽位覆盖、允许考点、难度配额、重复设计和冲突校验通过后原子保存未确认蓝图。确认后现有命题队列使用带设计字段的冻结槽位。

规划复用现有PostgreSQL任务表和outbox，键为planning:current，与current命题作业分开；不增加SQL迁移，不覆盖旧题目或旧作业。API只受理，Worker执行；重复提交/重投不重复计费。记录run_id、实际活动和usage。异常或崩溃后进入RECONCILING，不能自动重发。规划提交和结果落库均使用current草稿锁并核对规格、旧蓝图及活动命题作业。

迁移：旧规则预览接口停止生成并给出明确错误；前端显式按钮提交规划，改范围只失效计划，不隐式计费。需重新加载API、Worker、结构化输出代理及其新增contract挂载；无需清库。回滚只回退本次代码并正常重载；不得自动重放已受理任务。

当前限定：沿用现有本机教师接口，非生产身份授权；暂不支持共享材料规划。只校验结构与范围，不宣称教学合理性/数学正确性已证明；教师核对保留。规划最多一次调用，失败不伪造规则蓝图；超大卷可能触发现有输出token上限，需明确失败。
