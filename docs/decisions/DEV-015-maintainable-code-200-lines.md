# DEV-015：自有可维护代码单文件上限与目录整理

日期：2026-09-24。状态：ACCEPTED（用户明确提出，并确认适用范围）。

## 背景与选择

项目的前端页面、服务、工具和测试已有多处超长文件，影响定位调用关系、审查与交接。用户要求今后单个编码文件不得超过 200 行，超出即按职责拆分，同时整理目录与根目录杂项。

对前后端、工具、测试等自有可维护代码，以 200 个物理行为上限；不通过压缩语句或删必要说明凑数。第三方源码、生成物和已执行迁移除外。用 `tools/check_code_lines.py` 离线检查，并纳入 `quality/suites.yaml`。保持现有 CLI、API、页面入口与行为；按职责将实现移至同模块内的小文件。

`database/001_schema_draft.sql` 是冻结的 v1.3 数据模型设计资料，不是当前维护或执行的迁移脚本；检查器将它按参考文档排除。其余自有可维护 SQL 仍受行数检查。

## 影响与迁移

原 ZIP 的根目录说明及哈希清单归档到 `docs/archive/v1.4-bundle/`，根 README 改为当前项目导航。仍有用途的运行依赖锁文件与根部校验脚本保留；教材目录抓取脚本保留根部兼容入口。静态教材预览移到 `tools/crawler/` 并调整相对资源路径。用户上传资源和已有未提交代码保留。

本决策只改开发维护规则，不改变 v1.3 产品/接口基线；拆分期间发现的行为回归按缺陷修复，不能用“代码变短”代替功能验收。

## 回归与后续

检查原入口和直接调用方、定向单测、离线检查与前端构建。可见页面需在实际浏览器按桌面和窄屏操作，记录按钮、表单、导航、刷新及错误；由独立代理审查拆分是否丢功能。真实命题、数据库迁移、正式发布与产品签收另行验收。若未来确有单文件无法合理拆分，需先在新决策中说明例外及原因，不静默放宽门禁。
